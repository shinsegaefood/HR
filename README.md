# 인사이슈 보드

매일 오전 7시에 인사 관련 법령·판례·국회 의안·뉴스를 자동으로 모아 쌓고, 한 화면에서 보여주는 보드입니다.
공개 정보만 다루며, 인사검증 사이트(개인정보 도구)와는 별도 저장소로 운영합니다.

## 폴더 구성

| 위치 | 하는 일 |
| --- | --- |
| `index.html` | 보드 화면 |
| `config/settings.json` | 키워드·감시할 법령·내 도구 연결 (이 파일만 고치면 수집 대상이 바뀜) |
| `scripts/collect.py` | 매일 실행되는 수집 프로그램 |
| `.github/workflows/collect.yml` | 매일 오전 7시 자동 실행 설정 |
| `data/` | 수집 결과가 월별로 쌓이는 곳 (자동 생성) |

## 처음 한 번 해야 할 일

### 1. 인증키 신청 (모두 무료)

| 무엇 | 어디서 | 받는 값 | 비밀값 이름 |
| --- | --- | --- | --- |
| 국회 의안 | 열린국회정보 open.assembly.go.kr → 회원가입 → 마이페이지 → 인증키 발급 | 인증키 | `ASSEMBLY_KEY` |
| 뉴스 | 네이버 개발자센터 developers.naver.com → 애플리케이션 등록 → 사용 API "검색" 선택 | Client ID, Client Secret | `NAVER_ID`, `NAVER_SECRET` |
| 법령·판례 | 국가법령정보 공동활용 open.law.go.kr → 회원가입 → OPEN API 활용 신청 | 로그인 이메일의 @ 앞부분 (OC) | `LAW_OC` |

> **법제처는 주의가 필요해요.** 신청할 때 접속할 서버의 IP를 등록해야 하는데, GitHub 자동수집 서버는 IP가 매번 바뀝니다.
> 그래서 법령·판례는 처음엔 "403 접근 거부"로 실패할 수 있어요. 보드 상단에 실패 표시가 뜨고, 의안·뉴스는 정상 수집됩니다.
> 신청은 해두시고, 실패하면 알려주세요. 대안(공공데이터포털 경유 등)으로 바꿔드릴게요.

### 2. 새 저장소 만들기

1. GitHub에서 **New repository** → 이름 예: `issue-board` → **Public** → Create
2. **Add file → Upload files** → 이 폴더 안의 내용을 전부 끌어다 놓기 (`.github` 폴더 포함) → **Commit changes**
   - `.github` 폴더가 안 올라가면: **Add file → Create new file** → 파일 이름에 `.github/workflows/collect.yml` 입력 → 내용 붙여넣기 → Commit

### 3. 비밀값 등록

저장소 **Settings → Secrets and variables → Actions → New repository secret** 에서 위 표의 이름 그대로 하나씩 등록합니다.
키는 여기에만 넣고, 파일이나 채팅에는 붙여넣지 마세요.

### 4. 사이트 켜기

**Settings → Pages → Source: Deploy from a branch → Branch: main / (root) → Save**
1~2분 뒤 `https://<계정>.github.io/issue-board/` 에서 열립니다.

### 5. 첫 수집 돌려보기

**Actions 탭 → 매일 자동수집 → Run workflow**. 끝나면 보드를 새로고침하세요.
- 첫날은 기존 자료가 한꺼번에 들어오므로 NEW 표시가 붙지 않아요. 다음 날부터 새로 들어온 것에만 붙습니다.
- 실패 출처가 있으면 보드 맨 위에 노란 줄로 표시됩니다.

### 6. 인사검증 허브에 링크 달기

허브 `index.html`에 링크 카드 하나만 추가합니다 (코드는 섞지 않음). 원하시면 카드 코드를 만들어 드려요.

## 바꾸고 싶을 때

- **키워드·법령 추가**: `config/settings.json` 을 GitHub에서 연필 아이콘으로 수정 → Commit. 다음 수집부터 반영
- **수집 시간**: `.github/workflows/collect.yml` 의 `cron` 값 (UTC 기준, 한국시간 −9시간)

## 중요도 규칙

| 구분 | 조건 |
| --- | --- |
| 대응 필요 | 시행 30일 이내 법령, 내 도구와 연결된 법령이 최근 60일 안에 공포됨, 최근 30일 안에 본회의 가결된 의안 |
| 주시 | 최근 60일 공포 법령, 최근 30일 발의 의안, 최근 7일 안에 처리 단계가 바뀐 의안 |
| 참고 | 판례, 뉴스, 폐기·철회된 의안, 그 밖의 항목 |

메인 화면에는 "대응 필요", "주시", 최근 7일 뉴스·판례만 보이고, 나머지는 검색으로 찾습니다.
첫 수집 날 한꺼번에 들어온 자료는 메인의 "최근"에서 빠집니다.

## 뉴스 필터

`config/settings.json`에서 조정합니다.
- `news_title_keywords`: **제목**에 이 중 하나가 있어야 저장 (본문에만 나온 기사는 버림)
- `news_exclude`: 제목에 이 단어가 있으면 버림
- `news_trusted`: 매일노동뉴스·고용노동부 등은 "노동·임금·고용" 같은 일반 단어만 있어도 저장
- 필터를 바꾸면 다음 수집 때 기존에 쌓인 뉴스도 같은 기준으로 정리됩니다
- 제목이 비슷한 기사는 화면에서 하나로 묶여 "같은 소식 N건 더"로 보입니다
